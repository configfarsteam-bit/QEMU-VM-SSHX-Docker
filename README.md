# QEMU Web Terminal

یک ماشین مجازی Ubuntu داخل QEMU که با یک ترمینال وب (ttyd) و رمز عبور در دسترس است و آدرس عمومی آن را یک تونل cloudflared می‌سازد. آدرس در لاگ‌های docker چاپ می‌شود.

## این پروژه چه می‌کند

اسکریپت `qemu.sh` این کارها را به ترتیب انجام می‌دهد:

1. ttyd را روی `$PORT` راه می‌اندازد (با نام کاربری و رمز).
2. یک تونل cloudflared می‌سازد و آدرس `https://<random>.trycloudflare.com` را در لاگ چاپ می‌کند.
3. ایمیج Ubuntu 24.04 (noble) را دانلود و با SHA256 تأیید می‌کند.
4. VM را با QEMU بوت می‌کند (با KVM اگر موجود باشد، وگرنه شبیه‌سازی نرم‌افزاری TCG).
5. هر تب مرورگر از طریق ssh (با کلیدی که خود اسکریپت می‌سازد) به VM وصل می‌شود.
6. به‌صورت دوره‌ای اسنپ‌شات زنده می‌گیرد تا بعد از توقف کانتینر، VM از همان‌جا ادامه پیدا کند.

```
مرورگر ──https──> cloudflared ──> ttyd (رمزدار) ──ssh روی 127.0.0.1:2222──> VM اوبونتو
```

ttyd و cloudflared داخل **کانتینر** اجرا می‌شوند، نه داخل VM. VM فقط از طریق پورت لوکال `127.0.0.1:$SSH_PORT` و با کلید در دسترس است و مستقیم به بیرون باز نیست.

## پیش‌نیازها

اسکریپت به bash نسخه ۴.۴ یا بالاتر نیاز دارد و ابزارهای زیر باید در PATH باشند:

`qemu-system-x86_64`، `qemu-img`، `cloud-localds`، `python3`، `wget`، `ssh`، `ssh-keygen`، `sha256sum`، `flock`، `pgrep`، `getent`، `df` و ابزارهای معمول (`awk`، `sed`، `grep`، `head`، `tail`، `tr`، `cut`).

روی Debian/Ubuntu:

```bash
apt-get install -y qemu-system-x86 qemu-utils cloud-image-utils python3 wget \
  openssh-client procps util-linux ca-certificates
```

**ttyd** و **cloudflared** اختیاری‌اند. اگر در PATH نباشند، اسکریپت آن‌ها را از GitHub رسمی در `$VM_DIR/bin` دانلود می‌کند. ttyd با SHA256 تأیید می‌شود. برای cloudflared چک‌سام رسمی وجود ندارد و فقط اجرا شدنش بررسی می‌شود. برای محیط production بهتر است هر دو را داخل ایمیج نصب کنید.

دسترسی خروجی به اینترنت لازم است (دانلود ایمیج، cloudflared و ارتباط تونل). کانتینر باید با کاربری اجرا شود که در `/etc/passwd` وجود دارد (معمولاً root).

## شروع سریع

```bash
PAS='یک-رمز-طولانی' ./qemu.sh
```

`PAS` تنها متغیر اجباری است. بعد از چند ثانیه چنین بنری در لاگ می‌آید:

```
==================== WEB TERMINAL LINK ====================
https://random-words.trycloudflare.com
user: admin   password: the value of PAS
===========================================================
```

لینک را در مرورگر باز کنید. تا آماده شدن VM صفحه وضعیت بوت را نشان می‌دهد و خودش وصل می‌شود. روی TCG بوت اول ممکن است ۱۰ تا ۴۰ دقیقه طول بکشد.

## اجرا با Docker

نمونه Dockerfile:

```dockerfile
FROM ubuntu:24.04
RUN apt-get update && apt-get install -y --no-install-recommends \
      qemu-system-x86 qemu-utils cloud-image-utils python3 wget \
      openssh-client procps util-linux ca-certificates \
    && rm -rf /var/lib/apt/lists/*
COPY qemu.sh /usr/local/bin/qemu.sh
RUN chmod +x /usr/local/bin/qemu.sh
VOLUME /state
EXPOSE 8080
CMD ["/usr/local/bin/qemu.sh"]
```

اجرا:

```bash
docker build -t qemu-web .

docker run -d --name vm \
  -p 8080:8080 \
  -e PAS='یک-رمز-طولانی' \
  -v vm-state:/state \
  --memory=1g --cpus=2 \
  qemu-web

docker logs -f vm        # آدرس تونل را اینجا ببینید
docker stop -t 60 vm     # توقف با اسنپ‌شات نهایی
```

نکته‌ها:

- ولوم `/state` را حتماً دائمی بگیرید. ایمیج، دیسک VM و اسنپ‌شات‌ها آنجا هستند.
- برای توقف از `docker stop -t 60` استفاده کنید تا فرصت اسنپ‌شات نهایی باشد.
- اگر KVM دارید (`--device /dev/kvm`) سرعت چند برابر می‌شود.

## ورود به ترمینال

- در مرورگر پنجره Basic Auth می‌آید: نام کاربری `admin` (با `WEB_USER` قابل تغییر) و رمز همان مقدار `PAS`.
- داخل VM با کاربر `ubuntu` وارد می‌شوید. با `GUEST_ROOT_SHELL=1` (پیش‌فرض) مستقیم شل root (`sudo -i`) باز می‌شود.
- آدرس تونل در **هر استارت کانتینر تغییر می‌کند** و جزو اسنپ‌شات نیست.

## متغیرهای قابل تنظیم

همه با متغیر محیطی تنظیم می‌شوند. `auto` یعنی مقدار از روی منابع واقعی کانتینر محاسبه می‌شود.

### ضروری

| متغیر | توضیح |
|---|---|
| `PAS` | رمز ترمینال وب. خالی بودن خطا می‌دهد. کمتر از ۸ کاراکتر هشدار می‌دهد. |

### وب و تونل

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `8080` | پورتی که ttyd روی آن گوش می‌دهد |
| `WEB_USER` | `admin` | نام کاربری ورود (حروف انگلیسی، عدد، `.` `_` `-`) |
| `WEB_BIND` | `0.0.0.0` | آدرس IPv4 برای bind. با `127.0.0.1` فقط تونل دسترسی دارد |
| `WEB_MAX_CLIENTS` | `4` | حداکثر تب هم‌زمان |
| `SSH_PORT` | `2222` | پورت لوکال فوروارد به sshd داخل VM |
| `GUEST_ROOT_SHELL` | `1` | ۱ = شل root، ۰ = شل کاربر `ubuntu` |
| `CF_PROTOCOL` | `http2` | `http2`، `quic` یا `auto` |
| `CF_WAIT_SEC` | `60` | مدت انتظار برای اولین لینک تونل قبل از بوت VM |

### منابع

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `CPUS` | `auto` | تعداد vCPU. همان‌قدر که کانتینر واقعاً دارد |
| `MEMORY_MIB` | `auto` | RAM گست به MiB |
| `TCG_TB_SIZE_MB` | `auto` | کش کد TCG در RAM میزبان (۱۲٪ حد RAM، بین ۴۸ و ۲۵۶) |
| `HOST_RESERVE_MIB` | `auto` | ذخیره‌ی میزبان برای QEMU، ttyd، cloudflared و غیره (۲۰٪، بین ۱۶۰ و ۱۰۲۴) |
| `DISK_SIZE` | `auto` | اندازه‌ی دیسک VM. نمونه: `20G`، `512M` |
| `GUEST_SWAP_MB` | `auto` | فایل swap داخل VM. کمینه‌ی ۱۰۲۴ و یک‌هشتم دیسک |

### VM

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `VM_DIR` | `/state/ubuntu-vm` | مسیر ایمیج، دیسک، کلید و اسنپ‌شات‌ها |
| `FULL_VM` | `1` | اوبونتوی کامل بدون mask کردن سرویس‌ها. `0` = سبک‌تر |
| `CPU_MODEL` | `qemu64` | مدل CPU در حالت TCG |
| `MACHINE` | `pc,hpet=off` | نوع ماشین QEMU |
| `DISK_CACHE` | `unsafe` | `unsafe`، `writeback`، `none` یا `writethrough`. اگر کانتینر OOM می‌شود `none` را امتحان کنید |
| `DIRECT_KERNEL` | `1` | بوت مستقیم کرنل و initrd |
| `GUEST_APPARMOR` | `0` | فقط وقتی `FULL_VM=0` اثر دارد |
| `DISABLE_FLOPPY` | `1` | حذف فلاپی مجازی (رفع خطای `fd0`) |
| `SHOW_BOOT_LOG` | `1` | نمایش کنسول VM در لاگ تا آماده شدن |
| `BOOT_TIMEOUT_MIN` | `90` | حداکثر انتظار برای اولین ssh موفق |
| `GUEST_UNIT_TIMEOUT_SEC` | `900` | تایم‌اوت سرویس‌های systemd داخل VM |
| `IMAGE_BASE_URL` | آدرس noble/current | منبع ایمیج اوبونتو |
| `IMAGE_URL`، `KERNEL_URL`، `INITRD_URL` | از روی `IMAGE_BASE_URL` | آدرس مستقیم هر فایل |

### اسنپ‌شات و ادامه

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `RESUME` | `1` | ادامه از آخرین اسنپ‌شات |
| `SNAPSHOT_INTERVAL_MIN` | `20` | فاصله‌ی اسنپ‌شات‌ها. `0` = غیرفعال (ادامه ممکن نیست) |
| `SNAPSHOT_FIRST_DELAY_SEC` | `300` | تأخیر اولین اسنپ‌شات بعد از آماده شدن VM |
| `SNAPSHOT_TIMEOUT_SEC` | `600` | زمان‌بندی هر اسنپ‌شات دوره‌ای |
| `SNAPSHOT_STOP_TIMEOUT_SEC` | `20` | اسنپ‌شات نهایی هنگام `docker stop` (`0` = رد کردن) |
| `RESUME_TIMEOUT_SEC` | `180` | حداکثر انتظار برای شروع کار VM بازیابی‌شده |

## تعیین خودکار منابع

اگر مقدار را ندهید، اسکریپت از روی کانتینر محاسبه می‌کند:

- **CPU:** کمینه‌ی cpuset و سهمیه‌ی cgroup (v1 و v2). سقف مصنوعی ندارد.
- **RAM:** حد کانتینر منهای کش TCG و ذخیره‌ی میزبان، گرد‌شده به مضرب ۴. هیچ‌وقت به حد کانتینر نمی‌رسد.
- **دیسک:** فضای خالی ولوم `/state` منهای دو برابر RAM گست (برای اسنپ‌شات قدیم و جدید) و یک حاشیه‌ی ایمنی (۵٪، حداقل ۲۵۶MiB). فقط هنگام ساخت دیسک اعمال می‌شود. اندازه‌ی دیسک موجود تغییر نمی‌کند، چون qcow2 دارای اسنپ‌شات resize نمی‌شود. حداقل ۴۰۹۶MiB لازم است.

نمونه برای RAM (روی TCG):

| حد RAM کانتینر | کش TCG | ذخیره‌ی میزبان | RAM گست |
|---|---|---|---|
| 512 MiB | 61 | 160 | 288 |
| 1 GiB | 122 | 204 | 696 |
| 2 GiB | 245 | 409 | 1392 |
| 4 GiB | 256 | 819 | 3020 |

در بوت، خط `Resources:` مقادیر نهایی را در لاگ نشان می‌دهد. اگر مجموع مقادیر دستی از حد کانتینر بیشتر باشد، اسکریپت متوقف می‌شود و علت را می‌گوید.

## اسنپ‌شات و ادامه بعد از خاموشی

- هر `SNAPSHOT_INTERVAL_MIN` دقیقه یک اسنپ‌شات زنده (RAM و دیسک) در `/state` ذخیره می‌شود. VM در لحظه‌ی اسنپ‌شات کوتاه متوقف است.
- هنگام `docker stop` یک اسنپ‌شات نهایی (حداکثر `SNAPSHOT_STOP_TIMEOUT_SEC` ثانیه) گرفته می‌شود.
- با استارت دوباره روی **همان ولوم**، VM از اسنپ‌شات برمی‌گردد.
- بازیابی اسنپ‌شات دیسک را هم به همان لحظه برمی‌گرداند (ویژگی ذاتی اسنپ‌شات داخلی QEMU).
- اگر خود گست خاموش یا ریبوت شود، اسنپ‌شات دور ریخته می‌شود و استارت بعدی از دیسک (که جدیدترین حالت است) بوت سرد می‌کند.
- اگر تعداد CPU یا RAM نسبت به اجرای قبلی عوض شده باشد، اسنپ‌شات لود نمی‌شود و بوت سرد انجام می‌شود. داده‌ها حفظ می‌شوند.
- دیسک و اسنپ‌شات نسخه‌های قدیمی (sshx) ریزیوم نمی‌شوند، چون کلید ssh این نسخه را ندارند. یک بوت سرد انجام می‌شود و سرویس sshx قدیمی از گست پاک می‌شود.

## مثال‌ها

**ساده:**

```bash
PAS='my-long-password' ./qemu.sh
```

**نام کاربری و پورت دلخواه:**

```bash
WEB_USER=ali PORT=3000 PAS='my-long-password' ./qemu.sh
```

**شل ساده‌ی ubuntu به جای root:**

```bash
GUEST_ROOT_SHELL=0 PAS='my-long-password' ./qemu.sh
```

**فقط تونل به ttyd دسترسی داشته باشد:**

```bash
WEB_BIND=127.0.0.1 PAS='my-long-password' ./qemu.sh
```

**RAM و CPU دستی:**

```bash
MEMORY_MIB=384 CPUS=1 PAS='my-long-password' ./qemu.sh
```

**دیسک ۱۰ گیگابایت و swap دو گیگابایت:**

```bash
DISK_SIZE=10G GUEST_SWAP_MB=2048 PAS='my-long-password' ./qemu.sh
```

**اسنپ‌شات هر ۱۰ دقیقه و نیم‌دقیقه فرصت برای اسنپ‌شات نهایی:**

```bash
SNAPSHOT_INTERVAL_MIN=10 SNAPSHOT_STOP_TIMEOUT_SEC=30 PAS='my-long-password' ./qemu.sh
# docker stop -t 60 <container>
```

**بدون اسنپ‌شات (هر استارت، بوت سرد از دیسک):**

```bash
SNAPSHOT_INTERVAL_MIN=0 PAS='my-long-password' ./qemu.sh
```

**سبک‌تر کردن گست (سرویس‌های سنگین mask و AppArmor خاموش):**

```bash
FULL_VM=0 PAS='my-long-password' ./qemu.sh
```

**تونل با QUIC به جای HTTP/2:**

```bash
CF_PROTOCOL=quic PAS='my-long-password' ./qemu.sh
```

**کانتینر که با OOM کشته می‌شود:**

```bash
DISK_CACHE=none HOST_RESERVE_MIB=256 PAS='my-long-password' ./qemu.sh
```

## امنیت

- رمز طولانی و یکتا انتخاب کنید. ترمینال از اینترنت قابل دسترسی است و شل root می‌دهد.
- رمز از طریق env به QEMU، cloudflared و VM نمی‌رسد. فقط در آرگومان ttyd (داخل همان کانتینر) است.
- VM فقط از طریق `127.0.0.1:$SSH_PORT` با کلید ed25519 در دسترس است. ورود با رمز در گست غیرفعال است.
- کلید خصوصی در `$VM_DIR/ssh_key` با دسترسی `600` نگهداری می‌شود. ولوم `/state` را محافظت کنید.
- تونل cloudflared از نوع quick tunnel است: آدرس تصادفی دارد و ثابت نیست. برای آدرس ثابت باید tunnel نام‌دار تنظیم کنید که خارج از دامنه‌ی این اسکریپت است.
- روی پلتفرم‌هایی که health-check با HTTP دارند، ttyd بدون لاگین `401` برمی‌گرداند. TCP-check مشکلی ندارد.

## عیب‌یابی

| مشکل | علت و راه‌حل |
|---|---|
| `PAS is empty` | متغیر `PAS` را بدهید |
| `port ... is already in use` | `PORT` یا `SSH_PORT` را عوض کنید |
| `container RAM limit is ... less than 128 MiB` | حد RAM کانتینر را بالا ببرید |
| `only ... MiB free` | فضای ولوم کافی نیست (حداقل حدود ۴ گیگابایت به‌علاوه‌ی جای اسنپ‌شات). فضا آزاد کنید یا `DISK_SIZE` را دستی بدهید |
| `uid ... has no /etc/passwd entry` | کانتینر را با root اجرا کنید یا کاربر را اضافه کنید |
| لینک تونل نمی‌آید | `cloudflared.log` در `$VM_DIR` را ببینید. `CF_PROTOCOL=quic` یا `auto` را امتحان کنید. دسترسی خروجی به پورت 7844 لازم است |
| صفحه‌ی وب «VM is still starting» می‌ماند | روی TCG عادی است. خطوط `[vm]` در لاگ پیشرفت بوت را نشان می‌دهند |
| `did not accept ssh logins` | خطای ssh در همان پیام چاپ می‌شود. `BOOT_TIMEOUT_MIN` را بالا ببرید یا کنسول VM را بررسی کنید |
| کانتینر OOM می‌شود | `DISK_CACHE=none`، `MEMORY_MIB` کمتر یا `HOST_RESERVE_MIB` بیشتر |
| `another VM is already using ...` | یک نمونه‌ی دیگر روی همان `VM_DIR` در حال اجراست |
| ریزیوم انجام نمی‌شود | `resume failed` در لاگ را ببینید. معمولاً CPU یا RAM عوض شده. بوت سرد داده‌ها را حفظ می‌کند |

فایل‌های مفید در `$VM_DIR`: `serial.log` (کنسول VM)، `cloudflared.log`، `ssh-probe.log` (آخرین خطای ssh) و `web-shell.sh` (دستوری که ttyd برای هر تب اجرا می‌کند).
